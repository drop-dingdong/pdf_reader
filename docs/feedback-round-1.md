## 2. 缩放 —— 3 个问题，2 个已修

### 2.1 ✅ Ctrl+滚轮无法缩放

**根因**：egui 把 `Ctrl`+滚轮识别成**缩放**而不是滚动（`InputOptions::zoom_modifier`，
默认 `Modifiers::COMMAND`）。此时 `InputState::smooth_scroll_delta` 为 0，
倍率出现在 `InputState::zoom_delta()` 里。v1 只读滚动增量，于是这条路径完全没接上。

**修复**：`view::command_for_zoom_delta()` 把 `zoom_delta` 翻译成 `SetZoom(当前 × 倍率)`；
顺带获得触控板双指捏合缩放（egui 的多点触控走同一条路径）。
测试：`app::view::tests::zoom_delta_maps_ctrl_wheel_and_pinch`。

### 2.2 ✅ `Ctrl`+`+` 同时放大 UI 与页面（"这或许不是bug？" —— 其实是冲突）

**根因**：egui 内建 `gui_zoom::zoom_with_keyboard`（受 `Options::zoom_with_keyboard` 控制）
会用 `Ctrl`+`+`/`-`/`0` 缩放**整个界面**；而本应用同时把这些键映射成**文档缩放**，
两者一起生效，所以看起来"非显示区域也放大了"。

**修复**：构造时设 `options.zoom_with_keyboard = false`，这些快捷键统一由本应用解释为文档缩放。
代价：暂时没有"缩放界面 UI"的快捷方式（如需可在设置页里再提供，属 M2）。

### 2.3 ✅ 缩小时页面中心漂移（见附图）

**根因**：`PageLayout::clamp_scroll` 原先把偏移夹取到 `[0, max]`。当内容（页 + 留白）
比视口**窄/矮**时（缩得比较小的时候），偏移被夹到 0 → 页面被钉在左上角；
继续缩放时内容尺寸变化，视觉上就是"页面中心一直往左上跑"。

**修复**：改为**逐轴**判断 —— 内容小于视口的方向上让内容**居中**（偏移可为负），
否则照旧夹取。见 `layout::center_or_clamp`，测试
`layout::tests::content_smaller_than_viewport_is_centered`（断言页中心正好落在视口中心），
并记入决策记录 **D-09**。

### 2.4 ⏳ "顶部按钮缩放能保持纵向中心" —— 与 2.3 同一处修复

顶部按钮走的是 `SetZoom` → 会话的锚点逻辑（D-05）；2.3 修好后，
"内容小于视口"的情形也会稳定居中，不会再出现中心漂移。

## 4. 文本选择与复制 —— 已修

> "当前文本选择，无法相应复制键。后续需将鼠标拖动分设为两种模式…"

三个独立原因，全部处理：

| # | 原因 | 修复 |
| --- | --- | --- |
| a | 工具栏**搜索框持有焦点**时，`Ctrl+C` 被 egui 的 `TextEdit` 消费掉，应用收不到 | 在画布上按下（拖动/单击/双击）时主动 `memory.stop_text_input()`，让复制键回到应用 |
| b | **单击画布无条件清空选区**：选完随手点一下，选区没了，复制自然扑空 | 单击改为"命中文字就重新落点，点在空白才清空" |
| c | 拖拽语义只能靠"是否点到文字"猜，`Select`/`Pan` 不可控 | 工具栏新增**拖拽工具**三档：自动 / 平移 / 选字（`Tool`），并新增可见的**"复制"按钮**便于确认选区内容 |

测试：工具与映射的纯逻辑在 `view.rs`；选区/复制的数据流在
`pdfcore/tests/assemble.rs`、`pdfcore/tests/runtime.rs`（含"全选 + 复制跨页"）。

## 5. ✅ 空状态下拖放文件无效

**根因**：`App::ui` 在没有会话时**提前 return**，而读取 `dropped_files` 的代码写在那之后 ——
于是"启动后拖入 PDF"永远不触发。

**修复**：抽出 `handle_dropped_files()`，在 `ui()` 最开始（有无会话都）调用。

---

## 6. ✅ 侧栏边框拖动后松手回弹

**根因**：egui 的面板尺寸持久化键是 `parent_ui.scope_id().with_salt(id_salt)`，
而 eframe 每帧传入的是**新的根 `Ui`**（id 每帧不同）→ 上一帧的尺寸读不回来，
每帧都回到 `default_size(260.0)`。

**修复**：宽度改由应用自己保存（`sidebar_width`）—— 每帧把上次观察到的
`response.response.rect.width()` 作为 `default_size` 回填，并加 `size_range` 限制在 160–640。

## 7. ⏳ 文档搜索"无响应" —— 暂缓（已加提示）

> "文档搜索无响应暂时不需要解决，但因为其他的限制无法评价搜索结果的可信性。"

处置：
* 本轮**不修**搜索本身（按你的意见）；
* 但加了一处提示：0 命中时状态栏显示"未找到「关键词」（若 PDF 是扫描件则没有文本层，无法搜索）" ——
  因为**扫描件没有文本层**是最常见的"搜不到"原因，而不是搜索坏了。
* 待办（M2）：把搜索放到后台任务 + 命中列表侧栏，届时再评价结果可信性。
  若你手上有"能选中文字但搜不到"的具体 PDF，请给我一份，那就是真的 bug。
