# 诊断（现状）

> 所有诊断都写 **stderr**，只在对应开关打开时输出；格式面向"人眼比对日志"，
> 不是结构化日志。定位真机问题时按 §3 的顺序走。

## 0. 输出去处

所有运行期诊断都经过 [`Diagnostics`](../crates/app/src/diag.rs)：

* 正常运行时按 `PDF_READER_DIAGNOSE` 决定是否写 **stderr**；
* 回放模式（`--replay`）强制打开并**收集到内存**，按动作分组写进 JSONL（见
 [`testing.md`](testing.md) §4.5）。

失败类信息（存档解析失败、版本迁移说明）不走这里，直接写 stderr —— 它们很少发生。

## 1. 开关

| 环境变量 | 作用 | 默认 |
| --- | --- | --- |
| `PDF_READER_DIAGNOSE=1` | 打开全部运行期诊断（下文所有前缀） | 关 |
| `PDF_READER_TILE_BORDERS=1`（或 `true`） | 给每块瓦片描 2px 红线，便于肉眼分辨块范围与接缝 | 关 |
| `PDFIUM_PATH` | 指定 PDFium 动态库（见 [`../crates/backend-pdfium/README.md`](../crates/backend-pdfium/README.md)） | 自动查找 |
| `CHECK_PDF_FILE` | 只要存在，就在每次保存替换目标前，把暂存 PDF 复制到系统临时目录并调用 `qpdf --check`；qpdf 缺失只记录跳过，检查失败则不替换 | 关 |

`CHECK_PDF_FILE` 的检查结果是**消息记录**侧栏中的一条历史；它不改变正常保存消息。
qpdf 退出码 0/3（有警告）放行，其它退出码删除临时文件并保留原文件。
旧流程直接检查目标目录里的隐藏暂存名，实测 qpdf 会报 `Permission denied`；
现在检查系统临时目录里的副本，校验后立即删除。差别在 qpdf 打开的文件路径/
文件系统语义，不是 PDF 内容。副本保持复制后的默认权限，不额外 chmod。
若副本本身仍报
`Permission denied`/`Access is denied`/`unable to open`，视为**检查不可用**，
只记录跳过，不阻断保存。

示例：

```bash
CHECK_PDF_FILE=1 cargo run -p app -- <文件.pdf>
PDF_READER_DIAGNOSE=1 cargo run -p app -- <文件.pdf>
PDF_READER_DIAGNOSE=1 PDF_READER_TILE_BORDERS=1 cargo run -p app -- <文件.pdf>
```

## 2. 输出前缀与字段

### `[诊断]`（每秒一次，汇总）

```text
[诊断] 缩放=800% 视口=1200×900 scroll=(2782.5,2645.3) 当前页=9 可见页=[9,10] 纹理=34条/29.3MB 缓存在飞=2 预览中=false max_texture_side=16384 | 每页摘要
```

每页摘要（`|` 分隔）：

```text
p9 画法=瓦片 块=18/18 网格=16 渲染比例=10.486 等待=187ms 预览=Whole(2560) 底料=None 视图矩形=(x,y,w,h)
```

`位图=n条/x MB` 是**位图缓存**（CPU 侧，默认 512 MiB，`PDF_READER_BITMAP_BUDGET_MB` 可覆盖）
的占用——长时间高倍浏览时看它是否在预算附近进入平台期（这正是"不是泄漏、而是预算填满"的判据）。

`纹理=n条/x MB` 是纹理层的**字节账**—— 调预算、判断"是不是纹理占太多"
看这一项，而不是条目数（条目数相同的两张纹理面积可能差几十倍）。

### `[画法]`（**边沿触发**：某页画法变化时立刻打一行）

```text
[画法] p9 波段=10486 从=旧瓦片预览@6554 到=瓦片 就绪=18/18 等待=187ms 可见=Some((9,6,12,7)) 预览=Whole(2560) 层=2 底料=Whole(2560)
```

| 字段 | 含义 |
| --- | --- |
| `从/到` | 上一帧 → 这一帧的画法（`整页纹理` / `旧图拉伸` / `旧瓦片预览` / `瓦片` / `白底页框`）；`（兜底）` = 超时兜底 |
| `就绪=n/total` | 可见范围内已上传的块 / 有效块 |
| `等待` | 从"该波段第一块就绪"起的毫秒数（阈值 400ms） |
| `预览` | `preview_source` 的结论（整屏预览源） |
| `层` | 这一帧画了几层旧内容（底料 + 预览层） |
| `底料` | `underlay_source` 的结论；`None` = 没有任何旧像素可垫 |

### `[贴图]`（每上传一块新纹理一行）

```text
[贴图] 页=0 col=9 row=6 瓦片图=390x552 页面px=6242x8828 显示px=4762x6735 瓦片px=(3511,3310,390,552) 屏幕=(…,298,421) scroll=(…) 渲染比例=10.486
```

用途：区分"内容错位"（后端）与"摆放错位"（前端）。同波段内 `页面px` 与 `渲染比例`
只应出现**一个**值。

### `[瓦片]`（后端每渲染一块一行）

```text
[瓦片] 页=0 col=9 row=6 整页px=6242x8828 区域pt=(…) 期望=390x552 位图=390x552 原点=-3511 比例=10.486
```

### `[预览]`（预览图生成）

```text
[预览] 初次生成：… / …完成：… / …失败：…
```

见 [`persistence.md`](persistence.md) §4。

### 其它（按需）

| 前缀 | 内容 | 代码位置 |
| --- | --- | --- |
| `[帧]` | 每帧耗时分解（输入+pump / 纹理 / 绘制）；拖动期间或单帧 >25ms 才打 | `app.rs::draw_canvas` 末尾 |
| `[拖动]` / `[滚动]` | 拖动/滚轮的当帧状态与 scroll 前后值 | `app.rs::draw_canvas` / `collect_commands` |
| `[链接]` | 每页链接热区数与是否越界（越界 = 坐标空间不一致） | `app.rs::draw_canvas` |
| `[存档]` | 存档解析失败 / 版本迁移说明 | `app.rs::load_sidecar`、`open` |
| `[图片预览]` | 重选截图时合成失败的原因 | `app.rs::commit_custom_image` |

## 3. 排查路径

### 3.1 "某处是白的"

1. 看 `[画法]` 的 `底料=`：
  - `底料=Whole(2560)` → 那一块**有底料**，白说明是"底料也没盖到"（区域在页面之外？）；
  - `底料=None` → 该页**从未在整页波段渲染过**（超大页 100% 就分块）→ 真的没有旧像素；
2. 看 `就绪=n/total`：`n < total` 且 `到=瓦片` → 还在渲染（正常），400ms 后仍缺 → 某块失败或渲染太慢；
3. 看 `[瓦片]`：有没有对应块的渲染记录；没有 → 请求没提交（键/波段/可见范围的问题）。

### 3.2 "上下错位 / 重影"

1. `[贴图]` 的 `页面px` 是否**只有一个值**？多个值 = 同页混用了不同波段（INV-4/INV-8 被破坏）；
2. `[瓦片]` 的 `位图` 是否等于 `期望`？不等 → 后端尺寸校验会直接报错（`CoreError::Internal`）；
3. `[贴图]` 的 `屏幕` 与 `瓦片px × u` 是否一致？（`u = 显示px / 页面px`）

### 3.3 "缩放不跟手 / 掉帧"

看 `[帧]` 的三段：`纹理` 段大 → 上传/转换（拖动期间应被 `allow_upload=false` 抑制）；
`绘制` 段大 → 画的东西太多（浮窗/高亮/大纲行）；`输入+pump` 大 → 事件太多或命令处理重。

### 3.4 "预览图没有 / 只有一部分"

见 §3.1，再看 `[预览]` 三种失败信息（区域为空 / 不在页面内 / 块都为空）。

## 4. 已知不足

* 输出是 `eprintln!`，没有级别、没有落地文件、没有"上一次手势的完整轨迹"（拖动过程中看不了）。
* 前缀与字段是多年迭代长出来的，不同前缀的命名风格不统一（`页=` 与 `pN` 混用）。
* 没有结构化断言：只能人眼比对，无法进 CI。
