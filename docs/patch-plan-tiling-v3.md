# `feat/tiling-v3`：消除"波段切换时的白色填充"（已实施）

> 前置：D-94（渲染键/摆放改为波段）与 D-95（块矩形 + 尺寸校验）已落地。
> 真机反馈：**错位/重影已消失**，但缩放时仍有白色填充（缩小后原本有图的位置变白、
> 单向放大也会出现白块）。
>
> **状态**：§2–§4 已按本计划落地（D-97，一次提交、可整体 `git revert`）；
> 与计划的三处偏差见 §9「实施记录」。§6 的真机验收**尚未执行**（需要你的机器）。

## 1. 现状与成因（已定位，非渲染几何问题）

几何是对的：块的页面矩形、块位图尺寸、整页位图尺寸三者由同一个 `TileGrid` 导出，
真实 PDFium 下"块渲染 == 整页裁剪"逐像素一致（D-95 的测试）。白块来自**纹理保留策略**
与**画法判据**，两条叠加：

1. **纹理层只留"当前波段 + 最接近的另一个波段"**（`view::KeyedStore::retain_preview_scales`，
   [view.rs:996](../crates/app/src/view.rs)）。离开一个波段，它的纹理立刻被删；
   回到那个波段时只能靠 CPU 位图重传（`upload_page` 一次能传完该页所有已缓存的块），
   而**新露出的块**（缩小方向必然出现）必须现渲染（PDFium 串行，约 9ms/块）。
2. **画法判据是"任意一块就翻页"**（`has_tiles`，[app.rs:1967](../crates/app/src/app.rs)）。
   于是当前波段的**第一块**一到，整页就从"上一波段的整页拉伸/块拼预览"切成
   "当前波段瓦片 + 未就绪处 `paint_blank` 纯白"。波段切换后的 200–300ms
   （160ms 预览窗口 + 十几块 × 9ms）里，画面就是"几块清晰 + 大片白"。
3. 高倍下 `has_previous`（整页旧图）**几乎总是 `None`**：分块波段不产生整页图，
   更小波段的整页图又被第 1 条删掉了。于是缩小方向没有能盖满整页的底料，
   只能退到 `TilePreview`（上一波段的块，只覆盖当时可见的那一片）。

### 实测数据（模拟：A4 595.28×841.89，视口 1200×900，12 页文档，跳到第 9 页）

窗口无关的骨架（800%，`overscan = 1.6`）：

| 量 | 值 |
| --- | --- |
| 波段 / 渲染比例 | band 4 → `1.6^5 = 10.48576`，`u = 8/10.48576 = 0.76294` |
| 整页渲染像素 | `6242 × 8828`（≈55.1 MP，**210 MB**，所以必须分块） |
| 网格 | **16 × 16 = 256 块**（`level_for(8828)`） |
| 单块 | `390 × 552` px（0.82 MB），显示尺寸 `297.5 × 421.1` 内容像素 |

窗口相关的部分（可见块数 = 视口/单块显示尺寸，含"边缘不落边界 +1"）：

| 视口 | 可见块数 | 这些块的内存 |
| --- | --- | --- |
| 800×600 | 6 | 4.9 MB |
| 1200×900 | 15（滚动偏离边界时 18） | 12.3（14.8）MB |
| 1920×1080 | 21 | 17.2 MB |

沿 100% → 800% 走一遍（1200×900），纹理层/位图层留下什么：

| 缩放 | 渲染比例 | 网格 | 纹理档 | 块 / 整页 | 位图缓存(第9页) |
| --- | --- | --- | --- | --- | --- |
| 100% | 1.600 | 不分块 | 1600 | 0 / 1 | 1 键 4.9 MB |
| 160% | 2.560 | 不分块 | 1600, 2560 | 0 / 2 | 2 键 17.4 MB |
| 260% | 4.096 | 4 | 2560, 4096 | 8 / 1 | 10 键 33.5 MB |
| 410% | 6.554 | 8 | 4096, 6554 | 20 / 0 | 22 键 48.9 MB |
| 800% | 10.486 | 16 | **6554, 10486** | 30 / 0 | 40 键 63.6 MB |

结论：800% 时**整页图一张都不剩**，位图层里 5 档都在（≈64 MB）。所以
"缩回去"时既没有整页旧图可顶、又要等新块渲染 —— 而第 2 条让这等待直接显示为白。

## 2. 改动一：整页级"就绪门槛"（画法判据）

**一句话**：当前波段**可见范围内的块全部到齐**才切到瓦片；否则继续用整页级的旧内容顶住。

### 2.1 把决策从绘制里提出来（纯函数，可单测）

新增到 `crates/app/src/view.rs`：

```rust
/// 波段切换时可用的"旧内容"（整页级）。
pub enum Preview {
    None,
    /// 有整页图（任意波段）→ 拉伸显示；参数是该纹理的 scale_milli
    Whole(u32),
    /// 只有旧波段的块 → 按占比拼；参数是该纹理的 scale_milli
    Tiles(u32),
}

/// 一页在这一帧应该怎么画。
pub enum PageDraw {
    Whole,                 // 当前波段整页图在（不分块路径）
    Stretch(u32),          // 旧整页图拉伸（整页级）
    TilePreview(u32),      // 旧波段的块按占比拼（整页级）
    Tiles,                 // 当前波段的块（缺的补白）
    Blank,                 // 什么都没得画
}

/// 决策输入（全部是"已经知道的事实"，可构造后单测）。
pub struct DrawInput {
    pub tiled: bool,            // 该页当前波段是否分块（visible_tiles 是否 Some）
    pub has_whole_current: bool,// 当前波段整页纹理是否在
    pub ready: usize,           // 可见范围内"已在纹理层"的块数
    pub total: usize,           // 可见范围内有效块数（grid.contains 过滤后）
    pub preview: Preview,
    pub waited_ms: u64,         // 当前波段成为"当前"以来的时长
}

pub fn plan_page(input: &DrawInput) -> PageDraw;
```

决策顺序（**顺序即语义，测试逐条钉住**）：

| # | 条件 | 结果 |
| --- | --- | --- |
| 1 | `has_whole_current` | `Whole` |
| 2 | `!tiled` | `preview` 有整页图 → `Stretch`；只有块 → `TilePreview`；都没有 → `Blank` |
| 3 | `total > 0 && ready >= total` | `Tiles`（一块不缺，画出来不会有任何补白）|
| 4 | `ready > 0 && waited_ms >= READY_TIMEOUT_MS` | `Tiles`（**超时兜底**：某块渲染失败、或块太多时不永远停在糊图）|
| 5 | `preview` | `Stretch` / `TilePreview`（整页级旧内容）|
| 6 | 其它 | `Tiles`（首次打开、没有任何旧内容，白不可避免）|

`READY_TIMEOUT_MS` 初值取 **400ms**：比"160ms 预览窗口 + 十几块 × 9ms"略宽，
又短于用户感知的"画面卡住"阈值。

**与 D-88 的关系**：落笔仍然"整页一个来源"（要么整屏旧、要么整屏新），
**不是** D-87 那种"缺哪块就用旧块补哪块"的逐块混用。

### 2.2 `ready / total` 怎么数（必须与绘制用同一段枚举）

新增到 `crates/app/src/view.rs`：

```rust
/// 可见范围内"已在纹理层"的块数 / 有效块数。
///
/// 判定条件与绘制循环**完全一致**：`grid.contains(col,row)` 为真才算一块。
/// 两侧一旦不一致，就会出现"永远 ready < total"→ 永远停在预览（模糊）。
pub fn ready_tiles_in_view<V>(
    store: &KeyedStore<V>,
    page: PageIndex,
    rotation: Rotation,
    scale_milli: u32,
    grid: &TileGrid,
    range: (u32, u32, u32, u32),
) -> (usize, usize);
```

绘制循环里的 `total` 改为复用这个函数的结果（不再自己数），保证一致。

### 2.3 预览源怎么选（覆盖优先 vs 清晰优先）

`preview_source(store, page, rotation, target_milli) -> Preview`：

- 候选一：**整页图**——任一波段（`best_page_texture` 的键，取其 `scale_milli`）。
- 候选二：**块**——最近的有块波段（`best_tile_scale`）。
- 两者都有时：
  * **缩小方向**（块来自更高的波段、整页图来自更低的波段）→ 取**整页图**：
    缩小时视口覆盖的页面面积变大，旧块只覆盖"缩之前那一片"（800%→500% 只剩约 39%），
    整页图虽然糊，但**不会露白**；
  * **放大方向**（块来自更低的波段）→ 取**更接近目标**的那个：
    放大时旧块的覆盖是新视口的**超集**，块更清晰（比例差更小），没必要用更糊的整页图。

四个组合与取舍都写成表驱动单测（见 §4.1）。

### 2.4 等待计时器

`PdfReaderApp` 增加 `band_since: HashMap<PageIndex, (u32, Instant)>`（每页一条）：

- 每帧对可见页：若记录的 `scale_milli` ≠ 当前波段的 → 覆盖为 `(当前, now)`；
- `waited_ms = now - since`；
- 波段不变就不重置（滚动**不**重置计时器 —— 滚动时新块本来就慢，
  400ms 后应当显示"已就绪 + 补白"而不是一直糊着）。

## 3. 改动二：多留一档"整页图"（纹理保留策略）

`view::KeyedStore::retain_preview_scales` 由"当前 + 最近的一个其它波段"改为**至多三档**：

1. **当前波段**（`current_scale_milli`）；
2. **最近的其它波段**（现有逻辑，放大方向的预览底料）；
3. **当前比例以下、最近的"有整页纹理"的波段**（缩小方向的整页底料）——
   即 `max { scale < current | 该页在该 scale 上有 tile == None 的条目 }`。

其余全部丢弃。要点：

- 第 3 档必须按**页**独立选取（同页混合旋转的文档里，各页可用波段不同）；
- 整页纹理只会出现在"该波段不分块"的比例上（A4：1600、2560），因此这一档通常就是
  "上一次整页渲染的比例"，代价极小（一张 5–13 MB 的位图 / 一个纹理条目）；
- `TEXTURE_CAPACITY` 由 **64 → 128**：高倍下 2 个可见页 × (当前 18 块 + 上一档 18 块 + 1 整页)
  ≈ 74 条，再算上预取的相邻页，64 会开始抖（旧档的块被 LRU 挤掉 → 预览又缺料）。
  上限 128 条 × 单块约 0.8 MB ≈ 100 MB 显存（当前 64 条 ≈ 52 MB）；
- 保留规则仍是"每页 ≤ 3 档"，所以条目数由"可见块数"决定，不会随缩放手数增长。

## 4. 改动三：诊断（只在 `PDF_READER_DIAGNOSE=1` 时）

## 5. 测试清单（逻辑层，不需要窗口/GPU）

### 5.1 `plan_page`（表驱动）
1. `has_whole_current` → `Whole`（其余输入无关）。
2. 不分块 + 有整页旧图 → `Stretch`；只有旧块 → `TilePreview`；都没有 → `Blank`。
3. **关键回归**：`ready = 17/18` → 仍是 `TilePreview`；`ready = 18/18` → `Tiles`。
   （等价于"一块不能翻页"）
4. 超时兜底：`ready = 5/18`、`waited = 100ms` → 预览；`waited = 400ms` → `Tiles`。
5. 没有旧内容时 → `Tiles`（首次打开，白不可避免）。
6. `total == 0` 的安全路径（不 panic、不永远预览）。

### 5.2 `ready_tiles_in_view`
7. 与绘制循环的 `total` 一致：同一 range 下，空 store → `(0, total)`；插满 → `(total, total)`；
   插一块 → `(1, total)`；越界块（`grid.contains == false`）不计入 total。

### 5.3 `preview_source`
8. 只有整页图 → `Whole`；只有块 → `Tiles`；都没有 → `None`。
9. 缩小方向（块来自更高波段 + 整页图来自更低波段）→ `Whole`（覆盖优先）。
10. 放大方向（块来自更低波段）→ 更接近目标者；距离相等 → `Whole`。

### 5.4 `retain_preview_scales`
11. 构造 A4 走一遍的键集（1600 整页、2560 整页、4096 块、6554 块、10486 块），
    `current = 10486` → 保留 `{10486, 6554, 2560}`，其余删除。
12. 没有整页图时只留 `{current, nearest}`（与旧行为一致）。
13. 每页独立选取（两页可用波段不同）。
14. 现有测试 `retain_preview_scales_keeps_current_and_one_old_scale` 更新为三档语义。

### 5.5 现有测试
- `compose_snapshot` / 绘制映射 / D-94/D-95 全部不变（本改造不碰渲染与几何）；
- `KeyedStore` 增加的两个查询是只读，不影响既有 LRU 行为。

## 6. 验收（只能真机）

> 启动：`PDF_READER_DIAGNOSE=1 cargo run -p app -- <大页 PDF>`
> 先把缩放拉到 800%，再按下面的顺序做。

1. **缩小**（800% → 500% → 260% → 100%，可用滚轮逐步或 Ctrl+0 一次跳）：
   不应出现"整页白"或"大片白"；应看到整页旧图（可能偏糊）→ 一帧变清晰。
2. **放大**（100% → 800% 反向）：不应出现"几块清晰 + 大片白"；
   应整页旧内容顶住 → 块齐后一帧变清晰。
3. **同一波段内缩放**（100% ↔ 150%）：依旧完全无重渲染、无白（D-94 的行为不能退化）。
4. **滚动**（800% 下上下左右滚动）：允许未就绪处补白（新区域本来就没有旧内容），
   但**不允许**"已经清晰过的区域退回白色"；`[画法]` 不应反复在 `Tiles`/`TilePreview` 之间跳。
5. `[画法]` 行：一次波段切换应**只出现一次**从预览到 `Tiles` 的转换，
   且 `就绪=n/n`（或带 `兜底` 标记）；若大量出现 `就绪=3/18` 就翻页，说明门槛没生效。
6. 若出现"永远糊"（`[画法]` 一直是 `TilePreview`）：说明 `total` 统计与绘制不一致，
   或某块渲染失败 —— 把 `[画法]` 与 `[瓦片]`/`[贴图]` 行贴回来。

## 7. 风险与回退

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 切换从"渐进变清"变成"一次性变清" | 一次轻微清晰度跳变 | 这是 D-88 的取舍（宁可整页糊，不要拼盘）；真机若不能接受，再考虑"整页旧图打底 + 新块叠加"（需要重新评审 D-88） |
| `ready/total` 与绘制枚举不一致 | 永远停在模糊预览 | 复用同一个函数（§2.2）+ 专门测试；`READY_TIMEOUT_MS` 兜底 |
| 某块永久渲染失败 | 该页反复重提交 | 超时兜底至少让画面可用；失败仍在 `PageRenderFailed` 里报给状态栏 |
| 显存 64 → 128 条目 | 上限约 +50 MB | 保留规则仍是每页 ≤3 档；实测条目数见 §1 表 |
| 缩小方向仍有"从未渲染过"的区域 | 短暂补白 | 这是固有代价（没有旧内容）；§3 的第 3 档已把可覆盖范围最大化 |

**回退**：三处改动同一个提交，`git revert <sha>` 即可回到当前行为。
诊断（§4）可以单独保留 —— 即使回退画法/保留策略，它仍然有用。

**与计划的三处偏差**（都是落地时发现必须改的）：

1. **计时起点改为"该波段第一块就绪"**，不是"波段变化"。慢手势（滚轮按住 1 秒以上）
   期间波段不断变化；若从波段变化计时，渲染真正开始时早已超时 —— 第一块一到就触发
   兜底，白块又回来了。`DrawInput.waited_ms = 0` 表示"还没有任何块就绪"，
   此时不触发兜底（兜底还要求 `ready > 0`）。
2. **换文档时清空 `band_since` / `last_plan`**：两者按页号索引，跨文档会沿用旧文档的
   "第一块就绪时刻"，让新文档的同一页号一上来就判定超时。
3. **诊断格式**：`[画法] p9 波段=10486 从=旧瓦片预览@6554 到=瓦片 就绪=18/18 等待=187ms 可见=(5,7)-(10,9) 预览=Whole(2560)`；
   每秒的 `[诊断]` 摘要改成 `p9 画法=… 块=15/18 网格=16 渲染比例=10.486 等待=402ms 预览=…`。

**测试**（`cargo test --workspace`：199 passed，0 warnings）：

- `view::tests`：`plan_page` 六条（含"17/18 不翻页、18/18 翻页"这条关键回归）、
