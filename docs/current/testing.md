# 测试与验收（现状）

> 分工（见 [`../../agent.md`](../../agent.md)）：**逻辑层必须自动化**；
> 需要真实窗口/GPU 的部分交给用户人工验收，并在交付时说明"看什么"。

## 1. 命令

```bash
cargo test --workspace                 # 全部（208 个用例，含真实 PDFium 的 13 个）
cargo test -p pdfcore                  # 核心：几何/布局/分块/波段/调度/缓存/会话
cargo test -p app                      # UI 纯逻辑 + 存档 + 联调
cargo test -p backend-pdfium           # 真实后端（缺动态库时跳过，见 §4）
cargo test -p pdfcore --lib tiling     # 只跑某个模块
```

## 3. 测试基础设施（`pdfcore::testkit`）

| 替身 | 用途 |
| --- | --- |
| `MemoryBackend` / `MemoryDocument` | 假文档：批量页几何、导航索引、可配置密码 |
| `MemoryRaster` | 按页/块填纯色，块里编码 `(col,row,page)`；**执行与真实后端相同的契约校验**（尺寸/块矩形） |

| `MemoryCache` | 无淘汰的缓存替身（测试可直接 `clear()` 模拟 LRU 挤掉位图） |
| `LruCache` / `WorkerScheduler` | **真实**实现，也用于 `runtime.rs` 与 UI 联调测试 |

带大纲与链接、整页画满横线的多页文档），仓库里没有二进制夹具。

## 4. PDFium 缺失时的行为

`real_pdf.rs` 的每个用例开头 `let Some(backend) = backend() else { return };` —— **找不到动态库
就静默跳过**（只打印一行指引）。这意味着：CI 上没有 PDFium 时这些用例"绿得没有意义"。
准备动态库：

```bash
scripts/fetch-pdfium.sh          # 自动识别平台
```

## 4.5 回放器（`--replay`，D-103）

无窗口驱动**真实的 `App::ui`**，用脚本复现"缩放/滚动/跳页/悬停链接"，逐帧采集并检查四条断言。
实现在 [`crates/app/src/app/replay.rs`](../../crates/app/src/app/replay.rs)。

```bash
# 1) 生成样本（仓库不放二进制夹具；生成的 .pdf 已被 .gitignore 忽略）
cargo run -p app -- --sample a4 scripts/replay/a4_3p.pdf   # 也可 two-page / many / offset
# 2) 跑脚本（脚本里的 "pdf" 相对于脚本所在目录）
cargo run -p app -- --replay scripts/replay/tiling_800.json --out /tmp/out.jsonl
```

脚本格式（JSON，每个动作一个 `id`）：

```json
{ "name": "tiling_800", "pdf": "a4_3p.pdf",
  "actions": [
    { "id": "zoom_800", "op": "zoom", "value": 8.0 },
    { "id": "drag",     "op": "scroll_by", "dx": 420, "dy": 260 },
    { "id": "hover",    "op": "hover_link", "page": 0, "link": 0 }
  ] }
```

可用动作：`resize`（宽/高）、`zoom`（`value`）、`scroll_by`（`dx/dy`）、`set_scroll`（`x/y`）、
`go_to_page`（`page`，0 起）、`hover_link`（`page/link`）、`unhover`、`wait`（`frames`）。

### 4.5.1 确定性从哪来

| 机制 | 作用 |
| --- | --- |
| `Clock::manual()` + 每帧推进 20ms | 160ms 缩放预览窗口、400ms 就绪兜底、250ms 静默窗口都可复现 |
| 动作"稳定"判定 | 连续 3 帧**无在飞渲染 + 不在预览窗口 + 纹理与画法不变**才算结束（上限 240 帧） |
| 诊断缓冲（`Diagnostics::capturing`） | 每个动作的 `[画法]/[贴图]/[预览]/[诊断]` 归到该动作名下 |

### 4.5.2 四条断言

| # | 断言 | 判据（机械可判定） |
| --- | --- | --- |
| ① | **已清晰区域不得变白** | 每帧把画出的纹理四边形反算到页坐标 16×16 格子；曾用**当前波段**画过的格子，之后每帧必须仍被某一层（当前波段或旧内容）覆盖 |
| ② | **一次波段切换只翻一次** | 每个 `(页, 波段, 可见范围)` 内只允许 `预览 → 瓦片` 一次，且不得退回预览 |
| ③ | **预览尺寸 == 区域 × 分辨率** | 预览纹理的实际尺寸必须等于 `region_device_rect` 的结果（±1 边缘取整），与当前缩放无关 |
| ④ | **不得提前切到瓦片**（D-97 的编码） | 画 `Tiles` 时若可见范围没齐、又有旧内容可用、且未等满 400ms → 违规 |

③ 目前只在"存在自定义图片预览"时生效（回放脚本还没有"打开预览"的动作，S2 补）；
`region_device_rect` 本身已有单测与 `compose_region_snapshot` 共用同一套取整。

### 4.5.3 输出

JSONL 每个动作一行：`frames` / `settled` / `cpu_ms{p50,p95,p99,max}` / `upload_bytes` / `textures` /
`violations` / `notes` / `diag`。其中：

* `notes` = 不算违规但值得记录的观察（例如"以 9/12 块进入瓦片模式，等待 412ms"= 走了兜底）；
* `upload_bytes` = 本帧**打算**上传的像素字节（无 GPU，所以是"搬运量"而不是"上传耗时"）；
* 退出码：`0` 全部通过、`1` 有违规、`2` 脚本/打开失败。

### 4.5.4 断言有没有牙（实测）

把 D-97 的就绪门槛改回"有一块就翻"（`ready > 0`），同一脚本立刻报 **16 条**"提前切到瓦片"；
恢复后为 0 条。三条断言的判定逻辑本身也各有单测（`replay.rs` 的 `tests` 模块，10 个用例）。

### 4.5.5 它测不到什么

* 没有 GPU：纹理上传的真实耗时、填充率、显存占用都测不到（只能测"打算传多少字节"）；
* 字体渲染、系统字体缺字形、DPI 缩放等窗口相关行为；
* 交互动作（浮窗、侧栏、编辑）——脚本只覆盖主视图渲染主线。

## 5. 已知盲区

* ~~"决策 → 绘制"没有集成测试~~：已由 §4.5 的回放器补上（驱动真实 `App::ui` 并检查真实绘制输出）；
  仍未覆盖的是浮窗/侧栏/编辑等交互，以及下面这些。
* **没有性能基线**：渲染耗时、帧耗时、内存/显存峰值都没有自动测量，因此阈值与预算无法用数据回归。
* **没有 UI 自动化**：面板/浮窗/侧栏的交互全靠人工。
* `cargo fmt` 未统一（约 5.8k 行差异）、`cargo clippy` 有 56 条风格警告，都不在门禁里。

## 6. 人工验收清单（当前）

> 准备：`scripts/fetch-pdfium.sh` 一次；启动 `cargo run -p app -- <文件.pdf>`。
> 需要看日志时加 `PDF_READER_DIAGNOSE=1`（见 [`diagnostics.md`](diagnostics.md)）。

### 6.1 基础

| # | 操作 | 预期 |
| --- | --- | --- |
| 1 | 命令行打开 / 把 PDF 拖进窗口（**含尚未打开任何文档时**） | 显示第一页；状态栏"第 1 / N 页"与缩放比例 |
| 2 | 滚轮上下、翻页边界 | 连续跟手；新页进入视口不应明显卡顿 |
| 3 | 缩放到某词位于中央 → `Ctrl`+滚轮（或捏合） | 页面缩放，该词仍在中央附近 |
| 4 | `Ctrl`+`+ / - / 0` | 只缩放**文档**，界面不变 |
| 5 | 连续缩小到页面小于窗口 | 页面在窗口中居中（水平与垂直都留白） |
| 6 | 打开带 `/Rotate 90` 的页 | 文字正立、宽高正确 |
| 7 | 打开加密 PDF | 模态密码框；输错提示不崩溃；输对正常打开 |
| 8 | 上一页/下一页/目录条目/页码输入 | 目标页**顶部对齐**视口顶部 |
| 9 | 第三行菜单「横向」/ 勾选「横向滚动」 | 页从左到右一行排开；滚轮上下 → 横向移动；拖动正常 |
| 10 | 「全屏」/`F11` | 顶栏隐藏；指针靠近顶端时悬浮出现且**内容与正常模式一致** |

### 6.2 文字、链接与标注

| # | 操作 | 预期 |
| --- | --- | --- |
| 11 | 拖选文字 → `Ctrl+C` | 半透明蓝色高亮；粘贴得到文本（跨页以换行连接） |
| 12 | 双击某词 | 选中整词 |
| 13 | 搜索关键词回车 | 状态栏显示命中数；**命中位置居中**；黄=全部、橙=当前；上下可循环 |
| 14 | 点击页内链接 | 有落点 → 该点居中；只有页 → 顶部对齐 |
| 15 | 勾选「链接框」/「引用点」并缩放 | 75% 以上显示红框 / 圆圈标记；75% 以下隐藏 |
| 16 | 悬停带落点的链接 | 出现临时预览浮窗（首次可能需等待渲染）；点击它转固定；再悬停同一链接只高亮置顶 |
| 17 | 滚动/拖动时经过链接 | **不出现**悬停预览；静止约 250ms 后恢复 |
| 18 | 点击固定浮窗主体/标题栏 | 该浮窗置顶，其余相对顺序不变 |
| 19 | 浮窗内正文区拖动 | 移动浮窗（不拖 PDF 页面）；拖右下角改大小；✕ 关闭 |

### 6.3 自定义 preview、截图与存档

| # | 操作 | 预期 |
| --- | --- | --- |
| 20 | ＋文字/＋图片预览 → 点页 → 填题目 | 文字：对话框 save/关闭 保存；图片：进入截图模式，框选 Enter 保存 |
| 21 | Pin 状态下翻页/缩放/开关侧栏 | Pin **保持**；切到「选字」或「截图」才退出 |
| 22 | 侧栏「自定义preview」：悬浮 / 单击 / `→` / `✎` / `❎` | 临时预览 / 固定浮窗 / 跳转 / 改题目 / 删除（对应浮窗同步消失） |
| 23 | 截图模式下按 `Enter` / `Esc` | Enter 生成快照浮窗（自包含，之后缩放滚动不变）；Esc 静默退出 |
| 24 | 点「保存自定义数据」 | 生成 `<pdf>.json`（元数据，**不含像素**）；按钮上的 `*` 消失 |
| 25 | 改任意数据后再看保存按钮 | 变成 `*保存自定义数据` |
| 26 | 改浮窗大小 → 关闭 → 再从侧栏唤出 | 正文尺寸 = 上次改到的尺寸 |
| 27 | 打开旧版本存档（v1） | 提示"存档已升级到 v2，请保存"；保存按钮带 `*`；图片预览按 100% 重建（偏糊但**有图**） |

### 6.4 渲染判据（最关键的 5 条）

> 都在高倍（≥400%）下做；需要日志时 `PDF_READER_DIAGNOSE=1`。

| # | 操作 | 预期 |
| --- | --- | --- |
| 28 | 连续缩放跨多个波段后停止 | 同一行小字在块接缝处**不上下错开、不重影** |
| 29 | 缩放过程中 | 不出现成片白块。波段切换时整页旧内容（可能糊）顶住，块齐后一次性变清晰 |
| 30 | 800% 下拖动 | 未渲染的新区域显示**糊的整页底料**，不出现白块；已清晰的区域不会退回白 |
| 31 | 同波段内换比例（如 100% ↔ 150%） | 日志里**不出现新的 `[瓦片]` 行**；`[贴图]` 的 `页面px`/`渲染比例` 只有一个值 |
| 32 | 横向布局 + 大缩放向右滚动 | `scroll` 单调、无跳变 |

### 6.5 预览图判据

| # | 操作 | 预期 |
| --- | --- | --- |
