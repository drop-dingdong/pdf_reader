`real_pdf.rs` 的每个用例开头 `let Some(backend) = backend() else { return };` —— **找不到动态库
就静默跳过**（只打印一行指引）。这意味着：CI 上没有 PDFium 时这些用例"绿得没有意义"。
准备动态库：


## 4.5 回放器（`--replay`，D-103）

无窗口驱动**真实的 `App::ui`**，用脚本复现"缩放/滚动/跳页/悬停链接"，逐帧采集并检查四条断言。
实现在 [`crates/app/src/app/replay.rs`](../../crates/app/src/app/replay.rs)。

```bash
# 1) 生成样本（仓库不放二进制夹具；生成的 .pdf / .pdf.json 已被 .gitignore 忽略）
cargo run -p app -- --sample a4 scripts/replay/a4_3p.pdf
#    a4 / rotated / large / many / preview（preview 会一并写 sidecar）
# 2) 跑脚本（脚本里的 "pdf" 相对于脚本所在目录）
cargo run -p app -- --replay scripts/replay/tiling_800.json --out /tmp/out.jsonl
# 3) 全套脚本（9 个）作为回归网，一条命令：
cargo test -p app --test replay_scripts
```

### 样本（`replay::samples`）

| 名字 | 内容 | 覆盖的路径 |
| --- | --- | --- |
| `a4` | A4 三页，满页横线 | 分块、波段切换、滚动、跳页 |
| `rotated` | 两页，其中一页 `/Rotate 90`，带链接与大纲 | 旋转后的网格与摆放 |
| `large` | 单页 A0（100% 就 8MP） | 低倍即分块、整页位图很大 |
| `many` | 120 页 A4 | 跳页/布局、远处页面的按需渲染 |
| `preview` | A4 三页 + sidecar 一条图片 preview（记录分辨率 800%） | 存档 → 按记录分辨率请求渲染 → 拼图（断言 ③） |

样本都用 `backend_pdfium::fixtures` **现场拼 PDF**（纯字符串，不需要动态库）。
扫描件/JPEG 样本没有纳入：那类页面主要压 PDFium 的图像解码，对我们自己的分块/摆放逻辑没有新覆盖。

### 脚本（`scripts/replay/`）

| 脚本 | 样本 | 想守住什么 |
| --- | --- | --- |
| `tiling_800.json` | a4 | 400%→800%→拖动→退回：波段切换各翻一次、缺块补底料 |
| `band_walk.json` | a4 | 100→120→150→160→200→回退：同波段内改缩放不重渲染（`[瓦片]` 不新增） |
| `scroll_walk.json` | a4 | 400% 下四方向滚动：粘性瓦片（D-104）、不整页变糊、不露白 |
| `page_walk.json` | a4 | 200% 下 0→1→2→1 跳页：每页各自进门，互不干扰 |
| `rotated.json` | rotated | 300%/600% + 拖动 + 跳到旋转页：旋转后的块与摆放 |
| `large_page.json` | large | 100% 就分块的大页：整页位图不存在时的底料与兜底 |
| `many_pages.json` | many | 120 页里跳到 60/61/119/0：远处页面按需渲染 |
| `preview_100.json` / `preview_800.json` | preview | 同一预览在 100% 与 800% 下唤出，尺寸必须相同（断言 ③ 的"与缩放无关"） |

脚本格式（JSON，每个动作一个 `id`）：

```json
{ "name": "tiling_800", "pdf": "a4_3p.pdf",
  "actions": [
    { "id": "zoom_800", "op": "zoom", "value": 8.0 },
    { "id": "drag",     "op": "scroll_by", "dx": 420, "dy": 260 },
    { "id": "hover",    "op": "hover_link", "page": 0, "link": 0 }
  ] }
```

可用动作：`resize`（宽/高）、`zoom`（`value`）、`scroll_by`（`dx/dy`）、`set_scroll`（`x/y`）、
`go_to_page`（`page`，0 起）、`hover_link`（`page/link`）、`unhover`、`wait`（`frames`）、
`open_preview`（`index`：唤出第 index 条自定义图片 preview 的浮窗，走 app 自己的懒生成路径）。

### 4.5.1 确定性从哪来

| 机制 | 作用 |
| --- | --- |
| `Clock::manual()` + 每帧推进 20ms | 160ms 缩放预览窗口、400ms 就绪兜底、250ms 静默窗口都可复现 |
| 动作"稳定"判定 | 连续 3 帧**无在飞渲染 + 不在预览窗口 + 纹理与画法不变**才算结束（上限 240 帧） |
| 诊断缓冲（`Diagnostics::capturing`） | 每个动作的 `[画法]/[贴图]/[预览]/[诊断]` 归到该动作名下 |

### 4.5.2 四条断言

| # | 断言 | 判据（机械可判定） |
| --- | --- | --- |
| ① | **已清晰区域不得变白** | 每帧把画出的纹理四边形反算到页坐标 16×16 格子；曾用**当前波段**画过的格子，之后每帧必须仍被某一层（当前波段或旧内容）覆盖 |
| ② | **一次波段切换只翻一次** | 每次**连续逗留**某波段（离开再回来算新的一段）只允许 `预览 → 瓦片` 一次，且不得退回预览 |
| ③ | **预览尺寸 == 区域 × 分辨率** | 预览纹理的实际尺寸必须等于 `region_device_rect` 的结果（±1 边缘取整），与当前缩放无关 |
| ④ | **不得提前切到瓦片**（D-97 的编码） | **翻到瓦片的那一刻**若可见范围没齐、又有旧内容可用、且未等满 400ms → 违规（翻过去之后的部分块由底料补，属 D-104 的正常状态） |

③ 由 `preview_100.json` / `preview_800.json` 实测：两者都在 `open_preview` 后得到
**1573×839** 的纹理（= 150×80pt × 10.486，两端取整），与当前缩放无关；
`region_device_rect` 与 `compose_region_snapshot` 共用同一套取整。

### 4.5.3 输出

JSONL 每个动作一行：`frames` / `settled` / `cpu_ms{p50,p95,p99,max}` / `upload_bytes` / `textures` /
`violations` / `notes` / `previews`（`[下标,宽,高]`）/ `diag`。其中：

* `notes` = 不算违规但值得记录的观察（例如"以 9/12 块进入瓦片模式，等待 412ms"= 走了兜底）；
* `upload_bytes` = 本帧**打算**上传的像素字节（无 GPU，所以是"搬运量"而不是"上传耗时"）；
* 退出码：`0` 全部通过、`1` 有违规、`2` 脚本/打开失败。

### 4.5.4 断言有没有牙（实测）

把 D-97 的就绪门槛改回"有一块就翻"（`ready > 0`），同一脚本立刻报 **16 条**"提前切到瓦片"；
恢复后为 0 条。三条断言的判定逻辑本身也各有单测（`replay.rs` 的 `tests` 模块，10 个用例）。

### 4.5.5 它测不到什么

* 没有 GPU：纹理上传的真实耗时、填充率、显存占用都测不到（只能测"打算传多少字节"）；
* 字体渲染、系统字体缺字形、DPI 缩放等窗口相关行为；
* 交互动作（浮窗、侧栏、编辑）——脚本只覆盖主视图渲染主线。

## 4.6 性能基线（`--timing` + `--record` / `--compare`，D-106）

回放有两种 profile，同一份脚本两边都能跑：

| profile | 时钟 | 用途 | 能不能当门禁 |
| --- | --- | --- | --- |
| **确定性**（默认） | 手动时钟，每帧推进 20ms | 四条断言、结构指标 | **能**（跨机器一致） |
| **timing**（`--timing`） | 真实时钟 | 帧耗时、RSS、真实节奏 | 只做**同机**前后对比 |

```bash
# 记一次本机基线（release 才有意义；debug 的数字只能和自己比）
cargo run -p app --release -- --replay scripts/replay/tiling_800.json --timing \
    --record perf/tiling_800.json
# 之后比较（结构不符 → 退出码 1；时序回归 → 只提示）
cargo run -p app --release -- --replay scripts/replay/tiling_800.json --timing \
    --compare perf/tiling_800.json
```

基线文件长这样（`perf/` 已被 `.gitignore` 忽略 —— **每台机器自己记录**）：

```json
{ "version": 1, "script": "tiling_800",
  "machine": { "cpu": "AMD Ryzen 7 7730U…", "cores": 16, "ram_mb": 15329,
               "os": "linux", "arch": "x86_64", "build": "debug" },
  "actions": [ {"id": "zoom_800", "submitted": 12, "upload_bytes": 10327920,
                "textures_peak": 18, "preview": null} ],
  "cpu_ms": {"p50": 1.378, "p95": 2.096, "p99": 49.875, "max": 61.614},
  "rss_peak_kb": 86324 }
```

### 动作"稳定"的判定与帧预算（踩过的坑）

一个动作的结算条件是：连续 3 帧 **无在飞渲染 + 不在缩放预览窗口内 + 纹理与画法签名不变**。
其中"不在预览窗口内"这条是硬要求，因为窗口内应用**不提交渲染**。

于是帧预算不能只按"帧数"给：timing 模式用真实时钟，而预览窗口是 **160ms 墙钟** ——
release 构建下一帧可能只有 0.1ms，240 帧才 24ms，窗口都没过、渲染还没提交，动作就已经
用完预算。所以现在是**帧数 + 墙钟双上限**（20000 帧 / 5s），并且在"没稳定"的报错里直接
标出 `预览窗口=是/否`。

录制基线时如果出现下面任一情况，`--record` 会**拒绝**（退出码 1，不写文件）：

* 回放有违规；
* 整段脚本 `提交=0`（一次渲染都没发生，说明它根本没在测东西）。

比较时也会对"零渲染基线"直接判 `[门禁]`，避免拿一份假基线一路放行。

### 硬门禁（硬件无关）

| 指标 | 判据 |
| --- | --- |
| 动作序列 | 动作数与 id 必须一致 |
| `submitted` | **必须相等**（渲染请求数；"同一波段多渲一次"就是回归） |
| `textures_peak` | 必须相等（纹理保留策略的直接体现） |
| `upload_bytes` | ±10%（渲染完成顺序会轻微影响分帧） |
| `preview` | 必须相等（预览尺寸 = 区域 × 分辨率） |

### 只报告（硬件相关）

* `cpu_ms.p50 / p95 / p99` 超过基线 **+30%** → `[提示]`（`max` 只记录不比较：同一台机器两次能差 50%）；
* `rss_peak_kb` 超过基线两倍 → `[提示]`；
* 基线里的 `machine` 与当前机器不一致 → 先给一条 `[提示]`（"条件不同，时序只作参考"），
  结构指标仍然照常硬比。

## 6. 人工验收清单（当前）

> 准备：`scripts/fetch-pdfium.sh` 一次；启动 `cargo run -p app -- <文件.pdf>`。
> 需要看日志时加 `PDF_READER_DIAGNOSE=1`（见 [`diagnostics.md`](diagnostics.md)）。

### 6.1 基础

| # | 操作 | 预期 |
| --- | --- | --- |
| 1 | 命令行打开 / 把 PDF 拖进窗口（**含尚未打开任何文档时**） | 显示第一页；状态栏"第 1 / N 页"与缩放比例 |
| 2 | 滚轮上下、翻页边界 | 连续跟手；新页进入视口不应明显卡顿 |

| 5 | 连续缩小到页面小于窗口 | 页面在窗口中居中（水平与垂直都留白） |
| 6 | 打开带 `/Rotate 90` 的页 | 文字正立、宽高正确 |
| 7 | 打开加密 PDF | 模态密码框；输错提示不崩溃；输对正常打开 |
| 8 | 上一页/下一页/目录条目/页码输入 | 目标页**顶部对齐**视口顶部 |
| 9 | 第三行菜单「横向」/ 勾选「横向滚动」 | 页从左到右一行排开；滚轮上下 → 横向移动；拖动正常 |
| 10 | 「全屏」/`F11` | 顶栏隐藏；指针靠近顶端时悬浮出现且**内容与正常模式一致** |
