# PDF 1.4–2.0 注释字段差异速查

> 状态：2026-11-08 整理，**供排查/实现时查表**，不是 ISO 规范的替代品。
> 范围：本项目实际使用的五类注释 —— Text、Highlight、Underline、StrikeOut、Ink。
> 结论：**这五类注释在 1.5–1.7 之间没有需要分版本的注释字典差异；差异主要在文件结构
> （xref stream / object stream）。2.0 的核心字段也基本稳定，弃用项大多与本项目无关。**

## 1. 一句话结论

| 问题 | 结论 |
| --- | --- |
| 1.5 与 1.7 的注释字段有差异吗？ | 对这五类：没有需要分版本的字段差异 |
| 1.5 与 1.7 的差别在哪？ | 文件结构：1.5 引入 xref stream / object stream，1.7 也允许 |
| 1.4 能用吗？ | 核心注释字段基本沿用；是否支持是产品范围问题，不是格式硬边界 |
| 2.0 要单独一套吗？ | 不需要；核心字段沿用，先复用同一模型并补测试 |
| 要按版本复制读写代码吗？ | 不要；一套注释模型 + 文件能力判断 |

## 2. 版本与注释相关变化

| 版本 | 时间 | 注释相关变化 | 对本项目五类注释的影响 |
| --- | --- | --- | --- |
| PDF 1.4 | 2001 | 透明/`/CA` 等图形能力；文本标记注释已是标准能力 | 核心字段基本可用；是否纳入支持范围由产品决定 |
| PDF 1.5 | 2003 | **xref stream、object stream**、可选内容/图层、JPX | 注释字典不变；文件解析难度上升 |
| PDF 1.6 | 2004 | 更多注释/交互类型（如 3D、RichMedia 方向）、Measure 等 | 五类核心字段不变 |
| PDF 1.7 | 2006；ISO 32000-1:2008 | Redact 等新注释；现代 PDF 基线 | 五类核心字段不变 |
| PDF 2.0 | 2017；ISO 32000-2 | Movie/Sound 注释弃用、`NeedAppearances` 弃用、XFA/Flash 移除、UTF-8 字符串等 | 五类核心字段可沿用；弃用项基本不涉及 |

> 注意：上表是“版本规范层面”的变化，不是“每个文件实际使用”的保证。
> 一个 1.5 文件可以使用 object stream，也可以使用传统 xref；一个 1.7 文件同样可以。
> 版本号只能作为能力判断的线索，最终要看实际结构。

## 3. 五类注释的核心字段

以下字段在 1.5–1.7 中语义稳定，2.0 也基本沿用：

| 字段 | 含义 | 本项目用法 | 备注 |
| --- | --- | --- | --- |
| `/Type /Annot` | 对象类型 | 写回必写 | 所有版本一致 |
| `/Subtype` | 注释类型 | Highlight/Underline/StrikeOut/Ink/Text | 五类都是 1.4 起已有 |
| `/Rect` | 页面坐标包围盒 | 写回必写 | 坐标原点/旋转由页面决定 |
| `/Contents` | 正文 | 读写 | 文本字符串；UTF-16BE 是安全写法 |
| `/T` | 作者 | 读写 | 文本字符串 |
| `/M` | 修改时间 | 读写 | PDF 日期字符串 |
| `/CreationDate` | 创建时间 | 读回/写回 | 日期字符串 |
| `/NM` | 注释名称 | **`pd-fr:<id>` 标记** | 字节字符串；本项目身份锚点 |
| `/C` | 颜色 | 读写 | 0–1 数组 |
| `/CA` | 恒定透明度 | 读写 | PDF 1.4 起；不是 1.5 专属 |
| `/F` | 注释标志 | 写回含 `/F 4` | Print 标志；隐藏/NoView 读回跳过 |
| `/QuadPoints` | 文本标记四边形 | 高亮/下划线/删除线 | 每个 quad 8 个数；顺序固定 |
| `/InkList` | 墨迹路径 | 墨迹 | 点数组 |
| `/AP` | 外观流 | 下划线/删除线写；高亮不写 | 可选；Adobe 兼容另测 |
| `/Popup` | 弹窗引用 | 不写 | 不是核心字段 |
| `/IRT`、`/RT`、`/State`、`/StateModel` | 回复/审阅状态 | 不使用 | 版本前后有扩展；不属于本项目的核心契约 |

### 3.1 关于 `/QuadPoints`

- 文本标记注释用它表示逐行四边形，`x1 y1 x2 y2 x3 y3 x4 y4`；
- 本项目写回时每个 quad 的 8 个数字之间和**末尾**都必须有空白；
- 该字段不是 1.5 新引入的“版本差异字段”，1.5 与 1.7 的语义相同；
- 真正导致位置错乱的是写回时的 token 粘连（已由 `push_quad_points` 修复）。

### 3.2 关于 `/AP`

- Highlight 通常不写 `/AP`，让阅读器按 `/QuadPoints` + `/CA` 合成；
- Underline/StrikeOut 写线段 Form AP；
- `/AP` 是可选外观流，不属于 1.5/1.7 的版本分界；
- Adobe 是否显示属于**渲染器兼容性**问题，不是 PDF 版本问题。

### 3.3 关于 2.0

PDF 2.0 的弃用/变化主要不在上述字段：

- Movie、Sound 注释弃用；
- `NeedAppearances` 弃用（表单域外观，不是我们的文本标记）；
- XFA、Flash 移除；
- 文本字符串可使用 UTF-8；
- 文档信息字典部分弃用。

对本项目：

- `/NM`、`/QuadPoints`、`/Rect`、`/C`、`/CA`、`/Contents`、`/AP` 继续可用；
- 不建议为 2.0 复制一套注释模型；
- 先用 2.0 样本验证读写，遇到 2.0 特有结构再在“文件能力层”加开关。

## 4. 真正需要版本/能力判断的地方

不是注释字典，而是**文件结构与写回能力**：

| 能力 | 1.4 | 1.5 | 1.6 | 1.7 | 2.0 |
| --- | --- | --- | --- | --- | --- |
| 传统 xref table | 是 | 是 | 是 | 是 | 可能 |
| xref stream | 否 | 是 | 是 | 是 | 是/常见 |
| object stream | 否 | 是 | 是 | 是 | 是/常见 |
| 增量写回经典 xref | 是 | 是（需正确解析原结构） | 是 | 是 | 需验证 2.0 规则 |
| 五类注释字典 | 是 | 是 | 是 | 是 | 是 |

因此实现上建议：

```text
AnnotationModel（统一）
    ├─ read：PDFium 读注释
    ├─ map：/NM /QuadPoints /InkList ... 统一映射
    └─ write：统一字典/增量写回

FileCapability
    ├─ 解析 xref/object stream 成功？
    ├─ 能安全定位页对象/Annots？
    └─ 不能 → 只读或明确拒绝注释写回
```

## 5. 版本策略

### 5.1 `< 1.5`

按产品策略：**打开/渲染 PDF，但拒绝注释编辑**，信息栏说明：

> 当前 PDF 版本低于 1.5，本软件不启用注释功能；文档仍可阅读。

技术备注：1.4 的注释字典本身与 1.5 很接近，甚至可以兼容；但如果不打算维护，
就采用“拒绝注释而非拒绝打开”的策略，并保证不静默失败。

### 5.2 1.5–1.7

正常注释读写。必须支持：

- xref stream；
- object stream；
- 页对象 `/Annots` 定位；
- 五类注释的读写。

### 5.3 2.0

先按同一注释模型支持，补样本测试：

- 能读五类注释；
- 能写回并重读；
- 如果写回结构不兼容，则暂时降级为只读/拒绝注释写回，不复制整套模型。

### 5.4 版本识别

不能只看文件名或用户描述。至少检查：

1. 文件头 `%PDF-1.x`；
2. Catalog 的 `/Version`（可覆盖文件头）；
3. 实际结构能力（能否解析 xref/object stream）。

版本号用于**产品提示**，实际解析能力用于**是否允许写回**。

## 6. 测试与回归

后续 P0-C / 兼容性测试至少需要：

| 样本 | 目的 |
| --- | --- |
| 1.4 + Highlight/Underline | 1.4 是否纳入支持 |
| 1.5 + object stream/xref stream | 当前 `annotation_loss.pdf` 类问题 |
| 1.5 传统 xref | 排除“1.5 一定 object stream”的误解 |
| 1.6 + Ink/Text | 中间版本回归 |
| 1.7 + Highlight | 主干路径 |
| 2.0 + Highlight | 2.0 核心字段是否可复用 |

每类至少验证：

1. 读回注释（条数、id、几何、正文）；
2. 保存后重开（条数、id、几何、正文）；
3. 不再出现“期望数/实际数不一致”；
4. 不能安全解析时，明确降级，不静默 0 条。
