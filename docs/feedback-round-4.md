## 决定性证据

用户回传的诊断行（748%）：

```
[诊断] 缩放=738% 视口=513×576 scroll=(1716.4,2053.8) 当前页=1 可见页=[1] 纹理=10
        缓存在飞=0 max_texture_side=16384
        | p1 视图矩形=(-1679,-2042 3870×4785) 画法=瓦片 瓦片=6/6
```

三条关键信息：

1. `画法=瓦片 瓦片=6/6` —— 6 块瓦片**都已就绪、都执行了绘制**；
2. `视图矩形=(-1679,-2042 3870×4785)` —— 页面矩形本身完全正确；
3. `max_texture_side=16384` —— **不是 GPU 纹理上限问题**（页位图最大 4896×6336，远低于 16384），
   用户最初的怀疑可以排除（这条也顺手记录在此，免得以后重复怀疑）。

既然"都画了"却"看不见"，那只能是**画到了错误的位置**。

## 根因（D-17）

```rust
// v1（错）
page_rect.x + pixels.x / placement.scale.0
```

但本项目的内容空间有一条不变量：**内容空间单位在当前缩放下就等于该页位图的像素**
（`PagePlacement::rect` 已经是"页点数 × 缩放"，`pixel_size()` 就是取整后的 `rect.size()`）。
所以像素偏移换算到视图空间时应当**直接相加**，除以缩放是错的。

748% 时 `pixels.x / 7.38` 把 6 块瓦片（应占 3870×4785 的一大片）压缩到页面左上角
约 1/7 的小方格里；而视口落在页面中部 → 整块画布只剩深色背景 = **全黑**。
这也正好解释了你观察到的"**滚动时却有图片显示**"：滚到页面左上角就能看见那几块被压小的瓦片。

**修复与回归测试**：
* 新增 `view::tile_view_rect(page_rect, pixels)`，并在文档注释里写清这条不变量；
* 回归测试 `tile_view_rect_is_in_content_units_not_scaled` **直接用你给出的诊断数字**
  （`page_rect=(-1679,-2042 3870×4785)` + 瓦片 `(512,512)`），并断言"除以缩放的实现"会得到不同结果；
* 另外补了一条兜底：页面矩形**先铺白纸 + 1px 边框**再画内容 ——
  这样即使某块瓦片还没到，露出的也是白纸而不是深色画布。

## 缩放的"渐进式变化"与"非中心页面没有预览"

### ① 连续缩放的中间比例不该逐个渲染（D-18）

你说的没错：滚轮一次连续操作会产生一串中间比例（100→120→140→150），
v1 每一档都真的渲染 + 上传一次，所以每档都顿一下。

**修复**：缩放/旋转后进入 **160ms 预览窗口**——
窗口内**完全不提交渲染**（`SetZoom` 内部本来就会 `cancel_all`，队列随即清空），
停手后才渲染最终比例。中间的过场由旧内容顶上。

### ② 旧图拉伸此前对"非中心页"也失效，原因有两层

1. 高倍缩放走**分块**路径，缓存里根本没有"整页旧图"可拉伸，
   于是 `best_page_texture` 找不到东西 → 那些页显示成空白；
2. 即使有整页旧图，也只在"该页自身"命中时才用，跨页没有统一策略。

**修复**：
* 预览窗口内所有可见页统一走预览路径；
* 新增 `KeyedStore::best_tile_scale()` / `tiles_at()` 与 `view::tile_view_rect_scaled()`：
  **用上一档的瓦片按"新页像素 / 旧页像素"等比放大拼回整页**，
  于是高倍缩放下每一页也都有过场内容（诊断里会显示 `画法=旧瓦片预览 n/n`）。

## 请复验

| # | 操作 | 预期 |
| --- | --- | --- |
| 1 | 任意缩放到 **200%–800%** 之间来回 | **任何比例下都应看到页面内容**，不再出现整块黑屏 |
| 2 | 快速连续缩放（按住 Ctrl 连滚多格） | 全程显示旧内容（略微模糊），**停手后约 160ms 变成清晰图**；不再逐档卡顿 |
| 3 | 缩放到高倍后左右/上下平移 | 瓦片应严丝合缝拼接，没有错位或压缩到角落的现象 |
| 4 | 高倍下继续缩放，观察**非中心**的页 | 也应显示旧内容（不再是空白） |

仍然希望你在需要时附上 `PDF_READER_DIAGNOSE=1` 的诊断行——这次就是它一击命中的。

## 仍留在 backlog 的相邻问题

* **HiDPI 清晰度**：目前渲染比例 = 缩放比例（1 PDF 点 = 1 位图像素），
  在 1.5×/2× 缩放的显示器上会被 GPU 放大而略糊。修法是把设备的 `pixels_per_point` 乘进渲染比例
  （渲染与缓存键都不受影响，只是 scale 乘一个常数）——见 [backlog.md](backlog.md)。
* 预览质量的"档位化"（低倍预览 → 全清晰）目前用 160ms 窗口近似，
  更彻底的做法仍是 backlog 里的**视口空间渲染**。
