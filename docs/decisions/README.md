# 决策与背景（这一类文档是什么）

与 [`../current/`](../current/)（"现在是什么样"）互补，这里回答三件事：

| 文件 | 回答 |
| --- | --- |
| [`log.md`](log.md) | **做过哪些决策**（D-00a … D-101 索引 + 从 D-102 起的完整条目） |
| [`rationale.md`](rationale.md) | **为什么现在是这样**（按主题的架构说明与取舍） |
| [`history.md`](history.md) | **怎么变来的**（演进阶段、被推翻的做法、踩过的坑） |
| [`evaluations/`](evaluations/) | **动手前的评估**（可行性、风险、方案对比、待确认决策；例：S5 写回 PDF） |

## 1. 编号与状态

* ID 形如 `D-01`、`D-00a`（早期补遗）、`D-100`；**只增不改**，不复用。
* 状态：`有效` / `已取代（被 D-xx）` / `已回退`。
* 当前最大编号见 `log.md` 末尾；新决策从下一个编号开始。
* D-22、D-87 两个号没有独立条目：D-22 未使用；D-87 是一次被回退的尝试，只在 D-88 里留下结论。

## 2. 什么时候要写一条决策

满足任一条件：

1. 改变**架构或契约**（trait 方法、`RenderKey`/`RenderRequest` 形状、坐标系、线程模型）；
2. 改变**可观察行为**（画法、缓存保留、跳转语义、交互状态机）；
3. 改变**持久化格式**（存档字段/版本，另见 [`../current/persistence.md`](../current/persistence.md)）；
4. 引入或删除**常量/阈值**（分块阈值、overcap、超时）；
5. **回退/推翻**以前的决定（必须写清"取代了谁、为什么"）。

纯重构、纯文档、纯测试补充可以不写。

## 3. 条目格式（新条目用这个）

```markdown
### D-102 标题（一句话）

- **决定**：做了什么（可执行、可检验的陈述）
- **理由**：为什么（最好带实测数据/复现条件）
- **影响**：改了哪些文件/契约；对 UI、性能、内存、存档的影响
- **验证**：新增/更新的测试名；需要真机验收的项
- **回退**：怎么退（例如"单提交 `git revert`"）
- **状态**：有效
```

要求：

* "决定"必须能被别人**判真假**（不要写"优化了一下"）；
* "理由"里出现的每个数字都要说明来源（实测/推导/估算）；
* 涉及真机现象时，贴**日志片段**（不是描述日志）。

## 4. 历史原文

D-00a … D-101 的完整理由（当年那些长表格）保存在 git 历史里：

```bash
git show 778dc60:docs/decision-log.md
```

`log.md` 里的索引表是它们的**一行摘要**；`rationale.md` / `history.md` 是对仍然生效的那部分
的重新组织。**不要**再从 git 历史里抄回长表格——需要细节时按 ID 在旧文件里查。
